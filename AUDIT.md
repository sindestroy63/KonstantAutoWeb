# Технический аудит KONSTANT AUTO

Дата аудита: 26 июля 2026 года.

## Область аудита

Проверены конфигурация Next.js, TypeScript, TailwindCSS, PostCSS и ESLint, маршруты `app/`, компоненты, серверный API заявок, локальный каталог, публичные ресурсы, служебные скрипты, переменные окружения и README. Фактический стек до изменений: Next.js 14.2.18, React 18.3.1, TypeScript 5.9.3, TailwindCSS 3.4.15, npm lockfile v3.

Маршруты: `/`, `/catalog`, `/catalog/[slug]`, `/tracking`, `/contacts`, `/privacy`, `/api/leads`, `/robots.txt`, `/sitemap.xml`. Каталог содержит 148 статических записей и генерирует 148 страниц моделей во время сборки. Динамическими являются фильтрация каталога по query string и серверный `POST /api/leads`.

## Critical

### Уязвимая версия Next.js

- Файл: `package.json`, `package-lock.json`.
- Проблема: установлен Next.js 14.2.18. `npm audit` сообщает критические и high-уязвимости в Next.js; безопасное исправление предлагается только через major-upgrade.
- Последствия: в зависимости от схемы деплоя возможны DoS, cache poisoning, SSRF и обход middleware-защиты. Middleware в проекте нет, поэтому часть advisory неприменима, но RSC и Image Optimizer используются.
- Исправление: отдельно запланировать и протестировать переход на поддерживаемую актуальную major-версию Next.js вместе с React и ESLint-конфигурацией.
- Статус: требует решения владельца. Автоматический major-upgrade не выполняется как потенциально ломающий.

## High

### Неверный production-домен в SEO

- Файл: `app/layout.tsx`, `app/robots.ts`, `app/sitemap.ts`.
- Проблема: используется `https://konstant-auto.ru` вместо основного домена `https://константавто.рф`.
- Последствия: канонические сигналы и sitemap ведут на другой домен, возможны дубли и потеря индексации.
- Исправление: единая конфигурация сайта и production URL для metadata, canonical, robots, sitemap и structured data.
- Статус: исправлено. URL централизован в `lib/constants.ts`; Metadata API технически сериализует IDN в punycode.

### API заявок доверяет TypeScript-приведению входного JSON

- Файл: `app/api/leads/route.ts`, `lib/leads.ts`.
- Проблема: произвольный JSON приводится к `LeadRequestBody`; поля не проверяются по runtime-типам и длине. Значение неверного типа может вызвать исключение в `.trim()` и ответ 500.
- Последствия: отказ отдельных запросов, возможность создавать избыточную нагрузку и отправлять чрезмерно большие сообщения upstream.
- Исправление: runtime-парсинг, allowlist полей, ограничения длины, корректные 400/413, timeout и безопасная обработка ошибок upstream.
- Статус: исправлено.

### Отправка заявок не настроена текущим `.env`

- Файл: `.env`, `app/api/leads/route.ts`.
- Проблема: маршрут ожидает `LEADS_PROXY_URL` и `LEADS_PROXY_SECRET`, а локальный env содержит только устаревшие Telegram-переменные. Секретные значения в аудит не включены.
- Последствия: валидная форма получает 503 и не доставляет заявку.
- Исправление: документировать актуальные server-only переменные в `.env.example`; настроить HTTPS proxy URL и secret в окружении деплоя.
- Статус: требует решения владельца (нужны рабочие значения proxy).

### Публичные исходники изображений занимают 805 МБ

- Файл: `public/cars/*`, `app/page.tsx`.
- Проблема: 149 исходных JPEG/PNG находятся в runtime-папке `public`; один mockup загружает JPEG размером около 11,5 МБ. Каталог уже использует 148 оптимизированных WebP общим размером около 18,2 МБ.
- Последствия: тяжёлый деплой, лишнее дисковое пространство и очень дорогая загрузка изображения на главной.
- Исправление: перевести mockup на WebP; после проверки удалить исходники из runtime-папки или хранить их вне production-артефакта.
- Статус: исправлено. Mockup использует WebP, исходники перенесены без удаления в `reference/car-source-images`, `public/` уменьшен примерно до 28,2 МБ.

### Локальные credentials вспомогательного Telegram-бота

- Файл: `KonstantAutoTreckBot/.env`, `KonstantAutoTreckBot/google-creds.json`, локальные `.db` и virtualenv.
- Проблема: в workspace присутствуют приватные runtime-файлы отдельного Python-проекта; `google-creds.json` и базы ранее не были явно исключены root `.gitignore`.
- Последствия: случайная публикация токенов, Google credentials и персональных/операционных данных.
- Исправление: добавлены точечные правила `.gitignore`; проверить Git-историю и production-артефакты, удалить файлы из индекса и ротировать ключи, если они когда-либо публиковались.
- Статус: частично исправлено; ротация и проверка истории требуют решения владельца. Секретные значения не читались и не выводились.

## Medium

### Каталог не валидируется при загрузке

- Файл: `lib/catalog.ts`, `data/cars.json`, `data/modelImages.generated.json`.
- Проблема: JSON приводится через `as Car[]`; повреждённая запись обнаружится только случайной runtime-ошибкой. Текущие 148 записей фактически валидны, slug уникальны, рассчитанные изображения существуют.
- Последствия: одна ошибочная запись может сломать сборку каталога или страницу модели без понятной диагностики.
- Исправление: лёгкая встроенная runtime-валидация без новой зависимости, включая enum, числа, slug, дубликаты и image path.
- Статус: исправлено.

### Неполные SEO metadata и отсутствует structured data

- Файл: `app/layout.tsx`, страницы `app/**/page.tsx`.
- Проблема: нет canonical, полной Open Graph/Twitter-конфигурации, Organization/WebSite/Breadcrumb/Vehicle JSON-LD.
- Последствия: поисковым системам сложнее связать страницы, бренд и каталог; превью ссылок неполные.
- Исправление: добавить только подтверждённые данные без цен, рейтингов, отзывов и наличия.
- Статус: исправлено. JSON-LD сериализуется из типизированных локальных данных с экранированием `<`; HTML от пользователя не принимается.

### Нет защитных HTTP-заголовков

- Файл: `next.config.js`.
- Проблема: отсутствуют `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`, `X-Frame-Options`.
- Последствия: слабее базовая браузерная защита от MIME sniffing, framing и ненужных API браузера.
- Исправление: добавить совместимые заголовки. CSP не внедрять без nonce/infrastructure-плана, чтобы не сломать Next.js и внешние интеграции.
- Статус: исправлено для перечисленных заголовков; CSP оставлена рекомендацией владельцу.

### Типы route props соответствуют Next.js 15, а не Next.js 14

- Файл: `app/catalog/page.tsx`, `app/catalog/[slug]/page.tsx`.
- Проблема: `params` и `searchParams` объявлены как `Promise`, хотя в установленном Next.js 14 это обычные объекты. `await` объекта сейчас случайно работает.
- Последствия: вводящая в заблуждение архитектура и риск ошибок при обновлении типов/фреймворка.
- Исправление: привести props к контракту Next.js 14.
- Статус: исправлено.

### Недостатки доступности интерактивных панелей

- Файл: `components/Header.tsx`, `app/catalog/CatalogClient.tsx`.
- Проблема: мобильное меню не имеет `aria-controls` и Escape/route-close; фильтры не восстанавливают focus, поля поиска/select полагаются на placeholder/option вместо доступных подписей; пагинация не сообщает текущую страницу.
- Последствия: неудобная клавиатурная и screen-reader навигация.
- Исправление: добавить связи ARIA, управление focus, доступные label и `aria-current`.
- Статус: исправлено.

### Модальная форма входит в общий клиентский граф всех страниц

- Файл: `components/leads/LeadModalProvider.tsx`, `components/leads/LeadModal.tsx`.
- Проблема: большой компонент формы импортируется синхронно из root layout.
- Последствия: лишний клиентский JavaScript до первого открытия формы.
- Исправление: загрузить модальную форму динамически только при открытии.
- Статус: исправлено.

### README расходится с кодом

- Файл: `README.md`.
- Проблема: устарели порт, структура ресурсов, SEO-домен, фильтры, кнопки каталога, интеграция заявок и инструкции по изображениям; отсутствуют env, API, typecheck и deployment checklist.
- Последствия: ошибочная настройка разработки и production.
- Исправление: переписать README на основе кода и добавить безопасный `.env.example`.
- Статус: исправлено.

## Low

### Семантический `<main>` вложен в общий `<main>`

- Файл: `app/contacts/ContactsContent.tsx`, `app/layout.tsx`.
- Проблема: contacts-компонент возвращает второй `<main>` внутри layout.
- Последствия: некорректный landmark для assistive technologies.
- Исправление: заменить внутренний корень на `<div>`.
- Статус: исправлено.

### Sitemap меняет `lastModified` при каждой генерации

- Файл: `app/sitemap.ts`.
- Проблема: все URL получают текущее время независимо от изменений контента.
- Последствия: недостоверный сигнал поисковым роботам.
- Исправление: убрать искусственный `lastModified`, пока нет надёжной даты изменения данных.
- Статус: исправлено.

### Разрешены неиспользуемые внешние image-hosts

- Файл: `next.config.js`.
- Проблема: разрешены Unsplash и placehold.co, хотя runtime использует локальные изображения.
- Последствия: избыточная поверхность конфигурации Image Optimizer.
- Исправление: удалить неиспользуемые `remotePatterns`.
- Статус: исправлено.

### Мёртвые компоненты предыдущей версии главной

- Файл: неиспользуемые файлы в `components/home/`, `components/ui/`, `components/FooterLogo.tsx`, связанные данные и функции.
- Проблема: компоненты не имеют входящих импортов из действующего приложения.
- Последствия: усложнение сопровождения и ложное представление об архитектуре.
- Исправление: удалить только подтверждённо недостижимые файлы и экспорты.
- Статус: исправлено.

### Отсутствует typecheck script

- Файл: `package.json`.
- Проблема: TypeScript-проверка доступна только ручным вызовом `tsc --noEmit`.
- Последствия: проверку легко пропустить перед деплоем.
- Исправление: добавить `test:typecheck`.
- Статус: исправлено.

## Recommendations

- Перенести production proxy заявок на HTTPS. Статус: требует решения владельца.
- Добавить rate limiting для `/api/leads` на уровне reverse proxy/CDN: in-memory limiter некорректен для serverless и нескольких инстансов. Статус: требует решения владельца.
- Запланировать обновление Next.js/React/ESLint отдельной задачей с regression QA. Статус: требует решения владельца.
- Внедрять CSP только с nonce/hash и проверкой Next.js, Telegram/MAX/VK и аналитики в целевом окружении. Статус: требует решения владельца.
- Добавить автоматические интеграционные тесты API и browser smoke tests в CI. Статус: не исправлено.
